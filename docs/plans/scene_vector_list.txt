SCENE VECTOR LIST — WHAT IS TO BE DONE

The project collects ArkUI data from a HarmonyOS device and describes the
scene on the display. This list holds the work still to be done, in order,
and nothing else. What was done, and why, is in git and in the transcripts.

HOW THE LIST WORKS

- ORDER holds one line per item, in the order they run.
- PROMPTS holds each item's full prompt, starting "/cb-green — <title>" with
  no prefix, ready to paste.
- DEFERRED holds items kept for later, with their prompts. They are not run
  until the human moves them into ORDER.
- Each item is one skill execution.

When an item is finished, in the same session, before its gate is cleared:
- its line is deleted from ORDER and its prompt from PROMPTS;
- every later item it changes is written again to match;
- work it found and did not do is written as a new item in ORDER, with its
  prompt, or as an open point inside the item it belongs to;
- the list is committed, and the push is made through /cb-ops.

RULES FOR EVERY ITEM

- Specification first. Every node an item adds, modifies or removes is
  authored through ril before the code it governs. A removal of an
  invariant is confirmed by the human, node by node, before the envelope.
- No scene classes. A pattern names a structure of components; nothing in
  the repository maps a measurement onto the name of a scene, an app or a
  use.
- Only what is visible on the display enters a feature.
- Terms: the display is the coordinate space every area and fraction is
  measured in; a window is one top-level surface, and several coexist on a
  display; the screen is the physical panel, and is used only for motion.
- Sample timing is read from the capture's samples.csv, never from file
  times.
- Every figure an item reports is measured in that session on a real
  capture. npm run spec:check passes, and the checks that read the changed
  files are run and named.
- Before committing spec work: npm run ril -- journal coalesce.
- BOUNDARY: combobul and ArkUI are two projects. combobul/spec/spec.db holds
  the specification of this project's code, written only through ril. No
  rule, kind, check or store of one is carried to the other.
- The repository lives only on the VM. The capture machine reads it as a
  read-only share and runs the tools from ~\ark_work, where the captures,
  the venv and every output stay. Captures never enter the repository.

The baseline each item reads in full: README.md, tools/README.md, CLAUDE.md,
tools/rs_capture.ps1, tools/cluster/rs_extract.py, rs_pattern.py,
vectors_build.py, vectors_page.py, and the checks under tools/checks/.

/cb-green — the scene in one pass: visibility and patterns
  - What: the scene is the display's kept tree, built in one pass over the
    dump, and the pattern vector is matched inside that pass. Containment
    of the nodes actually on the display is the structure: neither the
    display nor a window is ever flattened into a set of nodes. It replaces
    the per-window walk, the owner window and the repeating-group detector.
    TERMS ON THE TREE, measured on the capture of 2026-10-28: every dump is
    RS_NODE / SCREEN_NODE / LOGICAL_DISPLAY_NODE / ...; the display is the
    one LOGICAL_DISPLAY_NODE, SCREEN_NODE's only child; a window is a
    top-level SURFACE_NODE under it, and a node belongs to a window by
    position, nothing else records it; no window owns the display. The
    display tree is not pre-clipped: of its 135,423 nodes 74 percent lie
    wholly on the display, 10 percent partly, 6 percent wholly off, 10
    percent have no area. Detached CANVAS_NODE subtrees hang at root level,
    outside it - 4,835 roots, a median of 9 percent of a dump's nodes - and
    are never read.
    STARTING STATE. The working tree and the DAG hold an unfinished run.
    rs_extract.py carries a broken split into index_dump, parse_node and
    parse_surface; rs_visibility.py, rs_pattern.py and tools/checks/
    geometry_visibility.py carry clipping, rotation as a quadrilateral,
    visible-cell areas and an owner selection; two spec batches are in the
    DAG and not coalesced. The batches are kept and amended as below; the
    code is rewritten to this design.
    THE SCENE. A node is in the scene if and only if it has visible cells
    of its own on the display, or a descendant in the scene. A kept node's
    children are exactly its kept children: a Column of 20 rows with 3 on
    the display is a Column of 3 rows. A node partly on the display is
    kept, and contributes only the cells that are visible. Every node
    wholly off the display, wholly occluded or at effective alpha 0 goes,
    with its branch, unless a descendant has visible cells of its own.
    Visibility is alpha alone (INV-OPACITY): at alpha 0 invisible; at alpha
    1 with a background alpha FF occluding; otherwise visible however
    transparent. No draw state - shouldPaint_, drawable slots,
    IsSubTreeSkipped - and no size threshold decides anything.
    THE PASS. The dump is indexed: one match per line gives each node's id,
    kind, line and parent. Then one descent from LOGICAL_DISPLAY_NODE,
    parent first, children topmost first (ReverseChildren, PositionZ).
      Down, inherited: effective alpha; the transform (Bounds, Translate,
        Rotation and Scale about the Pivot; a rotated node is a
        quadrilateral); the clip - the display, every clipping ancestor,
        and at a window node its VisibleRegion; the meaningful parent, the
        nearest kept ancestor whose tag is not pass-through; the window.
        A branch is dropped on the way down only when its region is
        provably empty: alpha 0, a clip with nothing left, or a clip
        region already wholly covered by occluders. A container that does
        not clip is descended even when its own box is off the display or
        occluded, because only its children decide whether it stays.
      At the node: its visible cells, against the occluders written so
        far - exactly those painted above it outside its branch.
      Up, returned to the parent: kept or not; its kept children; its
        element set to the dictionary's depth; the area of its branch's
        visible cells, each cell counted once; its pattern matches. An
        occluding node then writes its cells, and a mark claims its free
        cells for the surface vector. At a window node, its tag coverage
        over its kept nodes; a window under half tagged
        (ERR-PATTERN-ROOT-UNTAGGED) discards its matches and is named.
    Each node is visited once; a node's line is parsed only when the pass
    reaches it.
    VOCABULARY. Elements are written over meaningful component tags.
      - Pass-through, collapsed: __Common__, Custom, Stack, NodeContainer,
        RelativeContainer, and untagged nodes.
      - Size labels: XComponent:small under 0.15 of the display,
        XComponent:medium up to 0.5, XComponent:large above. Image and
        SymbolGlyph: icon when both sides are at most 56 dp and the aspect
        is 0.7 to 1.4; thumb under 0.15 of the display; image_large
        otherwise.
      - Element forms: Tag; parent/child, the parent being the nearest
        kept meaningful ancestor; parent/child* when two or more kept
        children are of that kind.
    DICTIONARY. Designed, not derived from any capture. Each pattern is a
    root and an element set:
      video_large    XComponent:large   {XComponent:large}
      video_medium   XComponent:medium  {XComponent:medium}
      video_small    XComponent:small   {XComponent:small}
      web            Web                {Web}
      gallery_flow   WaterFlow          {WaterFlow, WaterFlow/FlowItem*}
      gallery_grid   Grid               {Grid, Grid/GridItem*}
      list           List               {List, List/ListItem*}
      tab_bar        Tabs               {Tabs, Tabs/TabBar}
      text_input     TextInput          {TextInput}
      icon_row       Row                {Row, Row/icon*}
      icon_grid      composed: Column   {Column, Column/icon_row*}
                               or Grid  {Grid, Grid/GridItem*, GridItem/icon}
    MATCHING, on the way up. At a kept node whose label is a pattern's
    root: d = 1 - Jaccard(its element set, the pattern's set). Found when
    d <= 0.2. A found match is passed up as its pattern's token, so a parent
    can compose it; the parts it consumed, and inner matches of the same
    pattern, are dropped, so only the outermost counts.
    VECTOR, per display, at LOGICAL_DISPLAY_NODE. Per pattern: d, the
    minimum over its roots on the display, 1 when none; share, the area of
    its outermost matches' visible cells over the display area; count, its
    outermost matches, written n/(n+1). Every value lies in [0, 1] by
    construction, defined for every display, with no weight, no imputation
    and no normalisation across displays.
    VIEWER. The pattern tab holds one group per dictionary pattern: its
    picture, its definition, its count, and every scene it was found in.
    A scene appears under every pattern found on its display, and in a "no
    pattern found" group when none is. The picture is a schematic generated
    from the pattern's definition alone: the root a labelled box; children
    laid out by container kind - Row across, Column and List down, Grid and
    WaterFlow in two columns; a repeated child drawn three times with an
    ellipsis; sizes from the size labels.
    TIMING. A scene's picture is accepted only if no sample with a
    different signature lies between the dump's sample and the picture's
    sample in samples.csv; otherwise the scene is shown with no picture of
    its own and the reason is named.
    CLUSTERING. Runs on the pattern vector alone while the surface item is
    deferred.
    REMOVED AS DECIDED: the owner window; the media surface, which the
    video patterns cover; the OVERSIZE rule; the draw-state columns, which
    describe rendering, not the scene.
