SCENE VECTOR LIST — WHAT IS TO BE DONE

The project collects ArkUI data from a HarmonyOS device and describes the
scene on the display. This list holds the work still to be done, in order,
and nothing else. What was done, and why, is in git and in the transcripts.

HOW THE LIST WORKS

- ORDER holds one line per item, in the order they run.
- PROMPTS holds each item's full prompt, starting "/cb-green — <title>" with
  no prefix, ready to paste.
- DEFERRED holds items kept for later, with their prompts. They are not run
  until the human moves them into ORDER.
- Each item is one skill execution.

When an item is finished, in the same session, before its gate is cleared:
- its line is deleted from ORDER and its prompt from PROMPTS;
- every later item it changes is written again to match;
- work it found and did not do is written as a new item in ORDER, with its
  prompt, or as an open point inside the item it belongs to;
- the list is committed, and the push is made through /cb-ops.

RULES FOR EVERY ITEM

- Specification first. Every node an item adds, modifies or removes is
  authored through ril before the code it governs. A removal of an
  invariant is confirmed by the human, node by node, before the envelope.
- No scene classes. A pattern names a structure of components; nothing in
  the repository maps a measurement onto the name of a scene, an app or a
  use.
- Only what is visible on the display enters a feature.
- Terms: the display is the coordinate space every area and fraction is
  measured in; a window is one top-level surface, and several coexist on a
  display; the screen is the physical panel, and is used only for motion.
- Sample timing is read from the capture's samples.csv, never from file
  times.
- Every figure an item reports is measured in that session on a real
  capture. npm run spec:check passes, and the checks that read the changed
  files are run and named.
- Before committing spec work: npm run ril -- journal coalesce.
- BOUNDARY: combobul and ArkUI are two projects. combobul/spec/spec.db holds
  the specification of this project's code, written only through ril. No
  rule, kind, check or store of one is carried to the other.
- The repository lives only on the VM. The capture machine reads it as a
  read-only share and runs the tools from ~\ark_work, where the captures,
  the venv and every output stay. Captures never enter the repository.

The baseline each item reads in full: README.md, tools/README.md, CLAUDE.md,
tools/rs_capture.ps1, tools/cluster/rs_extract.py, rs_pattern.py,
vectors_build.py, vectors_page.py, and the checks under tools/checks/.

/cb-green — only what is on the display: clipping, rotation, visible area, owner
  - What: every algorithm that reads a node satisfies one invariant: only
    what is on the display is processed, and of a node only the part that
    is on the display. Four places break it today, measured on the capture
    of 2026-10-28 over 64,878 visible nodes in 300 scenes.
    CLIPPING. A parent with ClipToBounds[True] cuts what its children show
    to its own rectangle. 1,140 visible nodes lie wholly outside a clipping
    ancestor, in 298 scenes, and 10,541 partly outside. A node's on-display
    rectangle is its rectangle intersected with every clipping ancestor's,
    the display and its window's VisibleRegion; the walk measures that.
    ROTATION. Rotation, RotationX and RotationY are not composed. 1,889
    visible nodes in 72 scenes sit under a non-zero rotation. How a rotated
    rectangle is represented on an axis-aligned raster - its bounding box,
    or the rotated quadrilateral - is put to the human before the spec.
    VISIBLE AREA. A visible node enters a feature with its visible cells,
    never its whole rectangle. ALG-BRANCH-GROUP measures pat1_cover and
    overlay_frac from each member's rectangle clipped to the display only,
    so the occluded part of a visible node is counted. Every area any
    feature reports is a union of cells ALG-VISIBILITY found visible.
    OWNER. ALG-OWNER-SELECT, through window_weight, reads every node of
    every window before the walk runs. It runs after the walk instead, on
    each window's visible nodes and their visible cells.
  - Read: rs_extract.py (compose_geometry, window_weight),
    rs_visibility.py, rs_pattern.py (Scene, analyse, owner_of,
    media_surface, visible_surface), tools/checks/geometry_visibility.py;
    the property lines of one rstree dump carrying ClipToBounds and a
    Rotation.
  - Spec work:
      modify INV-VISIBLE-ONLY: no algorithm reads a node that is not on the
        display - feature columns and owner selection alike; a node is on
        the display when its on-display rectangle holds a cell no occluder
        outside its subtree covers.
      add invariant INV-VISIBLE-AREA-ONLY (SUB-FEATURE-RESEARCH, runtime):
        every area a feature reports is a union of cells ALG-VISIBILITY
        found visible, and no node contributes area beyond its own visible
        cells; checked-at AUT-PIPELINE-RUN.
      add invariant INV-CLIP-TO-BOUNDS (SUB-FEATURE-RESEARCH, runtime): a
        node's on-display rectangle lies inside every ancestor's that clips
        to its bounds; checked-at AUT-PIPELINE-RUN.
      modify INV-GEOMETRY-FROM-TREE: rotation, as the human decides.
      modify ALG-VISIBILITY: measures the on-display rectangle; satisfies
        INV-CLIP-TO-BOUNDS; returns every visible node's visible cells.
      satisfies INV-VISIBLE-ONLY and INV-VISIBLE-AREA-ONLY, each with the
        edge added: ALG-BRANCH-GROUP, ALG-VISIBLE-SURFACE,
        ALG-MEDIA-SURFACE, ALG-OWNER-SELECT. ALG-OWNER-SELECT calls
        ALG-VISIBILITY.
  - Code path: rs_extract.py, rs_visibility.py, rs_pattern.py,
    tools/checks/geometry_visibility.py.
  - Check: geometry_visibility.py tests the display, not agreement with
    the walk. It recomputes each admitted node's on-display region
    independently - exact rectangle arithmetic, no raster: the rectangle,
    intersected with every clipping ancestor, the display and the
    VisibleRegion, minus every occluding rectangle outside the node's
    subtree painted above it - and fails when:
      - a node any algorithm admits has an empty on-display region;
      - a node no algorithm admits has a non-empty one and alpha above 0;
      - a feature's reported area exceeds the union of its contributors'
        independently computed visible regions by more than the raster
        error of one 4 px cell per edge;
      - the owner chosen differs from the one chosen on visible nodes
        alone.
  - Test, on the real capture: the seven confirmed video rectangles still

/cb-green — the pattern dictionary and the matcher
  - What: the pattern vector, built from a designed dictionary of
    structural patterns matched against the visible components of each
    window. It replaces the repeating-group detector and the pattern
    columns entirely.
    VOCABULARY. Elements are written over meaningful component tags.
      - Pass-through, collapsed: __Common__, Custom, Stack, NodeContainer,
        RelativeContainer, and untagged nodes.
      - Size labels: XComponent:small under 0.15 of the display,
        XComponent:medium up to 0.5, XComponent:large above. Image and
        SymbolGlyph: icon when both sides are at most 56 dp and the aspect
        is 0.7 to 1.4; thumb under 0.15 of the display; image_large
        otherwise.
      - Element forms: Tag; parent/child, the parent being the nearest
        meaningful ancestor; parent/child* when that child kind occurs two
        or more times.
    DICTIONARY. Designed, not derived from any capture. Each pattern is a
    root and an element set:
      video_large    XComponent:large   {XComponent:large}
      video_medium   XComponent:medium  {XComponent:medium}
      video_small    XComponent:small   {XComponent:small}
      web            Web                {Web}
      gallery_flow   WaterFlow          {WaterFlow, WaterFlow/FlowItem*}
      gallery_grid   Grid               {Grid, Grid/GridItem*}
      list           List               {List, List/ListItem*}
      tab_bar        Tabs               {Tabs, Tabs/TabBar}
      text_input     TextInput          {TextInput}
      icon_row       Row                {Row, Row/icon*}
      icon_grid      composed: Column   {Column, Column/icon_row*}
                               or Grid  {Grid, Grid/GridItem*, GridItem/icon}
    MATCHING. A window with under half of its nodes tagged
    (ERR-PATTERN-ROOT-UNTAGGED, INV-CLIENT-TAG-COVERAGE) is not matched; it
    is named, and counts as untagged rather than as having no pattern.
    Per window, for each pattern, at every node ALG-VISIBILITY finds
    visible whose label is the pattern's root: the element set of its subtree down to the
    pattern's depth, through pass-through nodes; d = 1 - Jaccard(subtree
    set, pattern set). The pattern's distance in the window is the minimum
    over those nodes, and 1 when no node carries the root. Found when
    d <= 0.2. Matches of one pattern never overlap: only the outermost
    counts. Matching is bottom-up: a matched node becomes its pattern's
    token for the patterns above it, and parts consumed by a composed
    pattern are not counted on their own.
    VECTOR. Per pattern: d, the minimum over the windows on the display;
    share, the visible display area of the union of its matches, summed
    over the windows; count, the number of its matches summed over the
    windows, written n/(n+1). Every value lies in [0, 1].
    VIEWER. The pattern tab holds one group per dictionary pattern: its
    picture, its definition, its count, and every window it was found in.
    A window appears under every pattern it matches, and in a "no pattern
    found" group when it matches none. The picture is a schematic generated
    from the pattern's definition alone: the root a labelled box; children
    laid out by container kind - Row across, Column and List down, Grid and
    WaterFlow in two columns; a repeated child drawn three times with an
    ellipsis; sizes from the size labels.
    TIMING. A scene's picture is accepted only if no sample with a
    different signature lies between the dump's sample and the picture's
    sample in samples.csv; otherwise the scene is shown with no picture of
    its own and the reason is named.
    CLUSTERING. Runs on the pattern vector alone while the surface item is
    deferred.
  - Read: rs_pattern.py, vectors_build.py, vectors_page.py in full;
